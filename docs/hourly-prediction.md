# 整点公开观战与 WHITE

`/马币`现支持自动开户：未绑定游戏账号的QQ也能先开通1000马币并查询，但不能下注。完成账号认证后，再次查询或首次下注会自动核对同UID的游戏钱包，关联到同一YG身份；早期开通的QQ余额同步过去，不再发放一次开户余额。账号认证到期仍可查询自己的余额，下注需续期。封禁、撤销和已归属其他身份的账户不会自动转移。

自动关联由认证服务器验证UID哈希，签名票只含域隔离的QQ/游戏身份引用，不包含原始QQ、UID或隐私密钥。候选UID列表只通过专用机器人接口传递；若候选集变化，刷新证明后重试。QQ待结算持仓保留原账户，结算后再同步空闲余额；同步记账与绑定、初次开户原子落盘，重复命令不重发1000。已同步的旧QQ钱包不再触发低余额救济；签到目标同时更新，原签到日期保留。

服务端功能，兼容现有0.8.0客户端；不改已发布安装包和更新目录。

## 开盘与结算

WHITE 在整点场第10回合正式封盘（或提前结束）后，向本场通知群发送一张「本局互换马名」合并转发图。图上按选手编号、公开昵称和马名列出原属人与接收人，可区分两人互换和三人轮换；基础倍率随马名一起调换。临时停注不揭晓。名单独立于牌桌和战果的识别进度，每场只创建一份通知，按群确认送达。

北京时间每个整点先寻找原生均分达到6000（含6000）的公开八人新局；前5分钟没开成时，从第5分钟起降为严格大于5000（整数至少5001），仅补找到第10分钟。满10分钟立即停止选场及新开盘，下一整点重新从6000开始；开成一场后停止找下一场。02:00至06:00（包含两端）仍不开新场。对局必须在第1至2回合，候选固定按原生均分降序选择，同分选开局时间最新者，完全相同时按房间ID稳定排序；重复列表采用最新进度。这个门槛不使用Elo，只约束新开盘，已开场次及锁定权益继续保留。无合格对局、账号被其它采集器占用或当前公开场未结束时仅在选场窗口内等待，不打断原有观战。观察器在扫描后重新读取后台时钟和选场阶段，服务端开盘也核对当前阶段，不能通过修改本机时钟提前降档或绕过10分钟截止。

网站仍只展示一场公开赌马，其余房间留在游戏内。每整点最多开一次，重启不重复；尚未结算的整点场优先恢复，报价模型和马匹称号继续使用本局锁定值。

开盘合并转发的八张角色卡在档位旁标注该选手的原生“天梯 N分”或“道心 N分”。通过公开MatchPlayerInfosResp逐人读取分数及道心标记，名单UID集合完全一致后按本人匹配；不按整场gameMode推断，也不随马匹换档交换。分数在开局保存，仅开盘消息显示，后续战况与查询继续原样；Elo仍不公开。原生匹配资料暂不可读时只展示可核实的大厅天梯分，缺失不伪造零分、不阻塞持续观战。

普通房间维持原倍率。整点场在正常“基础倍率 × 本轮冻结的投注修正”之后再乘1.15；正常上限50倍先执行，专场最高57.5倍。只猜冠军，第一/第二/第三返还锁定权益的100%/25%/10%。第10回合起停止全部交易；若官方启用延迟观战，实际公开列表已经到第10回合也会封盘，不能利用较早的播放画面继续投注。退出角色不接受新投注。

回合图片显示各匹仍可预测马匹的当前冠军参考赔率，对阵表汇总最低至最高报价区间；区间取真实服务端报价，不推算未来涨跌。战况与报价分别注明回合，例如第8回合战况配第9回合参考赔率。战斗阶段显示暂停下注，第10回合起保留封盘说明和参考报价；已淘汰角色没有新投注报价。第9回合通知在合并转发第一个节点的第一句话提醒“下回合（第10回合）起封盘”，图片继续在同一合并消息内发送。

`/下注 1 200 2 300 1 200`支持一条命令按顺序下多笔，同一选手可重复；例中1号投入400、2号投入300，共700马币。每条最多32笔，每笔1～10000马币，整条共用原始群消息ID回执，所有子操作、余额与流水一同落盘。任一笔格式错误、余额不足、选手已退出、封盘或保存失败时全部回滚，不出现部分扣款；并发重试仍只执行一次。马匹称号与开局基础报价共用确定的换档分配，投注修正继续按真实投注量计算；已有客户端与观察器24组报价对照继续保留。

## Linux观战

`server/observer`使用专用账号已有的、由原采集服务续期的票据。它不注册账号、不启动Steam、不刷新或导出票据、不踢掉其它会话。加入前检查账号空闲，并持有原采集器同名的`public-observer-<sha256(uid)前20位>.lock`独占锁。锁文件须预先存在。退出时调用本次观战会话的正常离开并检查账号已空闲；清理失败会记录并阻止后续强占。

每次连接先读取官方服务器配置：普通观战使用原生GameStatus请求；官方启用延迟观战时只按原生快照及命令时间播放，不申请实时、裁判、好友等额外权限。名单必须与独立公开大厅名单的UID集合完全一致，不靠匿名序号、头像或位置猜身份。

只投影公开数据：昵称、档位、命元、胜负次数、角色、门派、境界、副职、已选仙命、公开战斗双方、上轮已使用牌及明确的胜者。普通仙命使用原生公开列表；百家仙命、天衍与共鸣仅使用公开上轮记录中的已选结果，标出已公开至哪一回合。忽略PrivateData、手牌、候选与私有仙命参数；内部Elo仅用于冻结报价，不出现在公开接口或群消息。普通观战的完整原始UID名单可能带镜像标记，不能因此拒绝整个GameStatus；战斗结果中的镜像副本仍不覆盖本人状态。

`export_build_catalog.py`从当前游戏资源生成名称字典，`export_public_art.py`导出显示素材；产物仅作为运行数据，游戏程序集、反编译源码、原始配置和完整资源包不入库。设置观察器`buildCatalog`路径。卡图按当前配置的基础卡、覆盖图片、融合输入卡及梦卡反向显示规则匹配；仙命按配置ID映射图标族，百家按原生类别使用独立图标、卡图、仙命图或融合图。PNG服务只开放固定种类及受限文件名，不公开源配置。缺图、未公开选择、未采集牌阵分别显示待同步或等待公开。

Python使用独立虚拟环境，依赖见`requirements.txt`。配置文件0600，复制`config.example.json`后填写专用观察密钥和本机票据路径；该密钥只授予`/ops/hourly`。提供的systemd单元以只读方式访问原采集目录，原Steam及采集服务无需重启。

```sh
python3 -m venv /opt/yx-duma-observer/venv
/opt/yx-duma-observer/venv/bin/pip install -r requirements.txt
/opt/yx-duma-observer/venv/bin/python update_card_names.py --output /var/lib/yx-duma-observer/card-names.json
/opt/yx-duma-observer/venv/bin/python main.py --config /etc/yx-duma-observer.json --once
```

正式运行使用`yx-duma-observer.service`。程序每15秒检查一次调度；入场后持续读取公开状态并同步，全部结果确认才派奖。观战断线后15秒内服务端自动暂停交易；恢复时重新校验名单及整局ID，数据缺失不编造结果。若房间已被官方回收、结果不完整，保留资金和未结算持仓供维护者核对，不另开新场掩盖它。

同一场只保留一个观战会话：后台拒绝/超时与大厅刷新失败不会触发退房重进。全局状态只取完整GameStatus，单桌BattleResult只补公开牌阵和战果；可选头像读取在全局状态上传后进行，大厅进度刷新采用单次短超时。短暂收不到状态继续等原连接，连接关闭或45秒没有有效状态才重连。后台保留明确拒绝原因；展示注解异常时可单独暂缓注解，核心身份、名次、封盘、报价和账目仍照常严格校验。

已结算场次中所有漏发回合的旁桌/镜像桌由独立`yx-duma-reports.timer`每20秒检查一次，不占用观战会话、不阻塞下一整点。`replayStore`可读取已有战绩库；`archiveBridge`指向部署者已有的`replay_service.py`目录，其`upstream(path, params, allow_missing=True)`接口复用现有账号票据与HTTP节流，只读取已结算对局的八个战绩视角，不登录或刷新账号。桥接在独立短进程中导入原战绩程序，避免与观战器的同名模块冲突，并禁用对原身份库的缓存写入；本服务的`archiveCache`仅保存筛选后的公开字段，每次最多补取四个缺失视角，可断点重试。完成身份核对后，按至多两回合、16桌分批补回全部待发回合，不仅限最后两回合。

战绩以对局编号和统一战绩头部限定范围；身份必须与直播中至少两轮真实公开牌组、角色及同轮出局名次区间一致，八人只有唯一完整对应时才通过。仅按匿名编号、名字、头像或单次排名不能通过。所有视角的牌组和胜者冲突均拒绝。补回操作只写公开战况与待发通知，不调用交易/派奖或刷新报价有效时间；通知照常通过WHITE合并转发，QQ确认成功后才确认送达。安装报告服务及timer后启用`systemctl enable --now yx-duma-reports.timer`；目录、票据和共享节流文件由部署者提供。原Steam、道心采集及战绩服务无需重启。

普通观战只轮询仍存活的公开头像，并在一次采集循环内连查缺失的公开对战；已获取同桌双方后跳过重复查询。收齐后停留在命元最低的存活角色以接收下一桌推送。原生普通头像入口不会重新请求已淘汰角色，故不再反复切换死者；漏掉的淘汰镜像桌可能只能等整局结束、原生战绩可读且八人身份唯一核对后补发，不承诺普通单连接能即时补齐所有桌。

公开角色资料另按选取回合保留历史，终局同轮状态更新不会覆盖上一轮仙命资料。补档接口可提交同局已保存的公开角色资料，仅写展示历史，不改当前游戏状态、报价或财务字段；完整性标志检查所有漏发回合，不能只凭最后一回合齐全就宣告完整。

原生lifeDamage是带方向的有符号值，负数同样合法。按规范化双方顺序交换时同时反转符号，图片按实际败方展示扣除的绝对数。观察器健康报告不刷新报价时间戳；校验中即时停投，原15秒有效状态时限和第10回合封盘继续生效。界面区分战斗等待、校验、重连、封盘和结算。

通知领取前重新组装并检查八人资料、当轮应参战者的公开牌阵及完整对阵；移除45秒后发送残缺内容的兜底。未齐的通知保留待重试，已经发送的通知不重发。首轮尚未发生的牌阵与尚未公开的选取明确标注；退出者沿用其最后一场完整公开记录。机器人缺少任何必需卡图或仙命图时不发送半成品，也不确认通知。资金结算后继续短暂收齐末轮公开资料，正常补齐即结束观战；资料一直缺失时保留待发，不伪造。

## 工具群

WHITE沿用现有OneBot连接，仅在工具群启用。每条命令重新验证QQ身份并取得最长60秒的签名票；开户和查询使用仅钱包权限，未绑定时保存为独立QQ主体。已有游戏绑定的主体与YG网页登录相同，自动关联并同步QQ余额。下注和调仓另需有效认证，交易票不超过认证剩余时长；封禁和撤销会阻断访问。已下注后的派奖不受后来认证到期影响。

| 命令 | 功能 |
| --- | --- |
| `/赌马` | 本场公开战况与玩法 |
| `/下注 1 100` | 向1号选手投入100马币，只猜冠军 |
| `/选手 1` 或 `/选手 完整昵称` | 查询指定选手的公开牌桌及战果 |
| `/马币` | 同一身份的可用马币与累计收益 |
| `/退半 1`、`/清仓 1` | 封盘前出售指定持仓 |
| `/赌马 查单` | 核对上一笔群内交易回执 |

交易使用原始群消息ID作为持久幂等键，跨对局重发也不会再次扣款；不确定的网络结果只重试同一ID。QQ成功回执后才确认用户已收到交易结果；未确认时，新下注先返回旧回执并说明本条未执行。禁止通过复制新消息盲目重投。

开盘和每回合战况使用合并转发，待当轮完整或进入下一轮后发送，结算另通知。转发节点中每名角色各一张图片，包含真实角色头像、八个牌位的公开卡图、普通及百家仙命图标，另附对阵表，注明双方胜负、原生战斗扣命元、公开战前战后命元和镜像。镜像损耗不记作本人扣命元，原生战斗伤害与命元净变化分开呈现；未采集到的历史扣血字段标记待同步。单独查询仅包含该选手及相关对阵；尚无本轮结果时可展示最近已公开回合并明确标注回合号。

最终结算图附结束语，并按下注身份列出本局累计投入、结算返还、出售回收和净收益，多个已绑定钱包按同一身份合并。净收益只按该局真实现金流计算，不包含签到、救济、绑定转账及其它对局；重放操作不重复计数，落盘失败整体回滚。不完整的旧流水明确待核对，不以当前余额猜历史收益。新场完整记录所有买入及出售；多名参与者的结算表自动分页，并在合并消息中发送，所有分组成功后才确认事件。

余额与交易回执保留简短文字。图像异步生成，中文字体使用运行机字体；生产端需安装Noto CJK，可用`PREDICTION_IMAGE_FONT`覆盖。通知队列落盘、带租约，合并图片获得QQ成功回执后才标记已发；发送成功但确认丢失时可能重复通知，不重复交易或派奖。未发送虚构开盘消息作为验收。

认证适配器保留在加载器私有仓库。公开MOD仓库只包含独立房间服务、专用权限接口及观察程序，不含管理员密钥、认证数据库或登录票据。

## 群内马币帮助、签到与转账

- `/马币帮助`：全部马币及赌马指令，不要求已有钱包或本场开盘。
- `/马币签到`：有效认证用户每日领取200马币，与网站使用相同身份、钱包、北京时间日期及签到流水；任一入口领取后另一入口不再发放。未开户时沿用原有自动开户规则。
- `/马币转账 @某人 200`：有效认证用户向工具群内真实@提及的一名成员转出200马币。收款人可以未认证或未开户，按原有规则开通钱包后收款；以后完成游戏绑定仍同步至同一钱包。自己、机器人、全体成员、多个提及和非正整数金额均不接受。

机器人先核对OneBot群成员，再分别取得发送人有效认证凭据和收款人钱包凭据；后台只接收签名的身份引用，不信任消息中随便填写的目标账号。转账余额、累计转入/转出、流水和QQ消息回执在同一事务落盘；同一原消息重试不重复扣款，任一错误整体回滚。新扣款仍需先确认上一笔回执，`/赌马 查单`可核对最近扣款结果。

转账不计入赌马净收益或排行榜输赢。转出余额不视为破产损失，不能用转空钱包反复触发50马币救济；同一QQ钱包迁移到游戏钱包时保留这些累计记录。普通未转账账户的救济条件保持。转账无额外手续费，可用余额范围内允许转完。


### 主动退出与迟到战果

整点后台保留已经确认的出局记录。退出角色收到迟到战果后胜负次数增加，且原生名次仍在已确认区间内（或暂未提供）时，不改出局轮次或已锁定返还。开局即退出和同一修炼阶段先后退出，按已公开的独立原生名次处理；需要公开战前命元与原生扣命元证明其不是该战致死，不能仅靠计数猜退出。正常战斗同出仍使用原有区间返还规则。
