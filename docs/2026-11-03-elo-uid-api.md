# MOD 按 UID 查询 Elo

当前名单准备评级时，客户端使用 `https://elo.kaigua.vip/api/v1/ratings` 查询实际需要的玩家。一个请求可以带1至8个24位小写十六进制UID，响应只包含查询到的玩家资料。`EloData.Url(uid)` 生成单人查询，`BatchUrl(uids)` 生成批量查询。

```text
GET /api/v1/ratings?uid=<UID>
GET /api/v1/ratings?uid=<UID1>&uid=<UID2>
```

响应是以UID为键的对象，客户端沿用 `rating`、`sigma` 和 `dx` 等资料字段。未收录玩家不在响应里，全未收录时返回 `{}`。网络失败与未收录分别显示，未知玩家保留 `Rating.Unknown()`。

请求按UID去重，AI、空槽和无效UID不发请求。一个八人名单通常只发一次查询，切换名单时最多保留四个并发任务。成功资料缓存300秒，失败或未收录缓存30秒，届时可以从新一代评分恢复。旧的按尾号分片地址和原站回退已移除。

Unity请求超时为8秒，客户端额外在未完成请求达到10秒后中止并释放，避免持续显示查询中。响应文本超过65,536个字符时拒绝解析。现有逐步JSON扫描仍在Unity主线程执行，共享每帧约2毫秒的软预算。停用MOD释放未完成请求。

本改动基于上游main整理。贡献方当前服务器已经提供按UID索引查询；接口响应形状与本客户端一致。账户、存档、评级公式和正式发布版本号保持原有规则。

验证结果：

- 实际 `EloClient` 配合离线Unity网络替身，48项检查通过，覆盖单人、八人、重复UID、AI/空槽、失败、未收录、重试、缓存过期、超时、超大响应和资源释放。
- 核心检查166项通过，UID URL构造和响应扫描也通过官方ILRuntime 2.1.0解释器探针。
- 游戏版net40 Release编译0错误、0警告，SDK静态检查0 error、0 warning，控制字节检查为空。
- 未启动游戏，未进行游戏内联网实测。此PR用于代码审阅，未覆盖正式Release附件或历史安装包。
